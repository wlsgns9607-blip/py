02 · 역할 분리

서비스는 4개의 층으로 나뉩니다

아래 레이어를 하나씩 눌러보세요. 각 층이 실제로 무엇을 책임지는지, 가계부 서비스를 예로 들어 보여드립니다.

사용자가 직접 보고 만지는 모든 화면

  • 대시보드, 거래내역, 카드관리 같은 화면 구성
  • 입력창, 버튼, 표, 그래프 등 UI 요소
  • 클릭·입력에 반응하는 사용자 인터랙션

중요: 이 층은 “보여주는 일”만 합니다. 데이터를 안전하게 지키는 일은 다음 층의 몫입니다.

화면 뒤에서 “판단하고 처리하는” 서버

  • 로그인 시 사용자 인증 / 권한 확인
  • 요청이 들어오면 DB에서 데이터 조회·저장
  • 네이버·카카오·날씨·AI 같은 외부 API 호출
  • 브라우저에 노출되면 안 되는 API Key 보호

Python은 화면을 그리는 언어가 아니라, 서버에서 “처리”를 담당하는 언어입니다.

서비스의 모든 기록이 남는 곳

  • 가계부라면 계좌 · 카드 · 거래내역 · 카테고리
  • 챗봇이라면 대화방 · 메시지 · 사용 기록
  • 사용자 A는 사용자 B의 데이터를 볼 수 없도록 권한 분리

React나 브라우저가 DB에 직접 접속하는 일은 없습니다. 항상 Python을 거칩니다.

서비스에 “지능”을 더하는 외부 엔진

  • 사용자의 질문을 프롬프트로 정리해 전달
  • AI의 응답을 가공해서 화면에 표시
  • 대화 기록·사용량을 Python이 관리

AI API도 결국 “외부 API”의 한 종류입니다. 원리는 날씨 API, 지도 API와 같습니다.

FastAPI를 사용한 교육용 코드 예제로 핵심 보안 개념을 배웁니다.

🐍 Python + FastAPI 예시 코드
import os
from fastapi import FastAPI, Header, HTTPException

app = FastAPI()

# ✅ 환경변수에서 API Key를 불러옵니다 (코드에 직접 쓰지 않습니다)
AI_API_KEY = os.getenv("AI_API_KEY")

@app.post("/chat")
def chat(message: str, authorization: str = Header(None)):

    # 1️⃣ 인증: 로그인한 사용자인지 확인
    if not authorization:
        raise HTTPException(
            status_code=401,
            detail="로그인이 필요합니다."
        )

    # 2️⃣ 입력값 검증: 너무 긴 메시지 차단
    if len(message) > 500:
        raise HTTPException(
            status_code=400,
            detail="메시지가 너무 깁니다."
        )

    # 3️⃣ 비밀정보 확인: API Key가 설정되어 있는지 점검
    if not AI_API_KEY:
        raise HTTPException(
            status_code=500,
            detail="API Key가 설정되지 않았습니다."
        )

    return {
        "message": "AI API 요청을 서버에서 처리합니다."
    }
1️⃣

인증 (Authentication)

이 사용자가 로그인한 사용자인가?

2️⃣

인가 (Authorization)

로그인한 사용자가 이 기능을 사용할 권한이 있는가?

3️⃣

입력값 검증 (Validation)

사용자가 이상하거나 너무 큰 데이터를 보내지는 않았는가?

4️⃣

비밀정보 관리 (Secret Management)
